    Best Practices

    Summary¶

    Anthropic's official guide to writing effective Skills for Claude Code. It emphasizes treating the context window as a scarce shared resource, calibrating instruction specificity to task fragility, and organizing skill content via progressive disclosure (one level of reference depth). The guide also covers naming conventions, description-driven discovery, multi-model testing, and breaking complex workflows into checklists.

    Key Claims¶

    • The context window is a shared public good; every token in a loaded SKILL.md competes with conversation history, so conciseness matters even though skills are lazily loaded.
    • Instruction freedom should be calibrated to task fragility: high freedom for flexible tasks, low freedom (exact scripts) for brittle or safety-critical operations.
    • Skill discovery depends entirely on the description field; it must specify both what the skill does and when to trigger it since Claude selects from potentially 100+ skills.
    • Reference files should be kept one level deep from SKILL.md to avoid partial reads from nested references.
    • Skills should be tested across all target models because what works for Opus may need more detail for Haiku.
